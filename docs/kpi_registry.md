# Реестр KPI: надёжность и экономика

Единый реестр ключевых показателей с формулами, целевыми значениями и способом
контроля. Все показатели вычисляются расчётным ядром (`src/fuelcontour/engine`) и
проверяются автотестами.

Обозначения: `y` — год; сумма по `y` — по горизонту 2035–2040; `млн` — млн у.е.

---

## 1. KPI надёжности / сервиса

| KPI | Формула | Цель | Где считается | Как контролируется |
|---|---|---|---|---|
| Общий сервис (год) | `service_total(y) = issued(y) / demand_total(y)` | ≥ 97% | `engine/service.py` → `YearRow.service_total_ratio` | `engine/constraints.py::_check_service`; тест `test_constraints` |
| Критический сервис (год) | `service_crit(y) = served_crit(y) / demand_crit(y)` | ≥ 99% | там же | там же; в стрессе — обязателен, проверяется отдельно |
| 45-дневный резерв | `reserve_req(y) = demand_total(y) × 45/365` | `stock_start(y) ≥ reserve_req(y)` | `constraints.py::_check_reserve` | предупреждение по году; тест `test_reserve_45_days_formula` |
| Лимит Emergency | число лет подряд, где E — основной (>50% отбора) | ≤ 2 | `constraints.py::_check_emergency` | ошибка при превышении |
| Ожидаемая недопоставка канала | `E[недоб] = Σ_y delivered(y) × (1 − reliability(y))` | минимизировать | `engine/risk.py` | реестр рисков; вход в Монте-Карло |
| P(критич. соблюдён) | доля прогонов МК, где `crit ≥ 99%` все годы | как можно выше | `engine/montecarlo.py` | `montecarlo`; сравнение планов |
| VaR-95 дефицита | 95-й перцентиль суммарного дефицита по прогонам МК | контроль хвоста | `montecarlo.py::p95_shortfall` | детерминизм по seed |

## 2. KPI экономики

| KPI | Формула | Цель / лимит | Где считается | Как контролируется |
|---|---|---|---|---|
| Переменный платёж (канал, год) | `price × max(order, take_or_pay × reserved)` | минимизировать | `economics.py::variable_payment` | тесты V03/V04, `test_economics` |
| Плата за резерв | `rate × reserved × year_fraction` | минимизировать | `economics.py::reservation_payment` | тест V05 |
| Стоимость хранения | `storage_cost × (stock_start + stock_end)/2` | минимизировать | `economics.py` | `test_economics` |
| Потери (год) | `loss_rate × inflow` (один раз) | снижать (ZBO) | `balance.py` | тест V06, `test_losses_once` |
| CAPEX до 2037 | `Σ capex(инвестиций с финансированием ≤ 2037)` | ≤ 1800 | `economics.py::capex_cumulative_2037` | `constraints.py::_check_capex` |
| CAPEX суммарный | `Σ всех capex` | ≤ 2800 | `economics.py::capex_cumulative_total` | там же |
| Суммарные расходы | `Σ_y (capex + var + reserve + storage + opex)(y)` | минимизировать | `economics.py::total_cost` | дашборд + выгрузка |
| Дисконтированные расходы | `Σ_y year_cost(y) / (1+r)^(y−base+1)`, r=0.07 | сравнение стратегий | `economics.py::total_discounted` | единая ставка во всех сравнениях |
| Стоимость тонны обсл. спроса | `total_cost / Σ_y served_total(y)` | снижать | `economics.py::cost_per_ton_served` | KPI эффективности |

## 3. Формула материального баланса (базовый инвариант)

```
stock_end(y) = stock_start(y) + inflow(y) − losses(y) − issued(y)
stock_start(y) = stock_end(y−1),  stock_start(2035) = initial_stock
0 ≤ stock_end(y) ≤ storage_capacity
```

Контроль: `engine/balance.py`; тесты `test_balance_identity`, `test_no_negative_stock`,
контрольный пример V01.

## 4. Целевые значения (сводка)

| Показатель | Целевое значение |
|---|---|
| Критический сервис | ≥ 99% (обязательно во всех сценариях) |
| Общий сервис | ≥ 97% (стандартный сценарий) |
| CAPEX до 2037 / суммарный | ≤ 1800 / ≤ 2800 млн |
| Физический резерв | ≥ 45 дней спроса |
| Emergency как основной | ≤ 2 лет подряд |
| Надёжность ISRU 1-го года | ≤ 0.78 (консервативно) |

## 5. Способ контроля (как это работает на практике)

1. **Автоматически при каждом расчёте.** `engine/constraints.py` возвращает список
   нарушений `{год, тип, величина, лимит, причина}` — они видны на экране «Проверки»
   и в выгрузке.
2. **Уровни.** Нарушение обязательного ограничения — `error` (план неисполним);
   ориентир устойчивости (напр. сервис в стрессе) — `warning`.
3. **Регрессия.** Формулы KPI зафиксированы автотестами (74 шт.) и контрольными
   примерами V01–V10 (`python -m fuelcontour validate` → 10/10).
4. **Мониторинг рисков.** `montecarlo` даёт вероятностные KPI (P(сервис), VaR), а
   `sensitivity` — вклад каждого параметра в расходы (торнадо).
