# Руководство пользователя

## Топливный космоконтур 2035 — как пользоваться

Документ описывает запуск и работу с расчётным контуром: веб-интерфейс,
командную строку и импорт данных.

---

## 1. Запуск

### Быстрый старт (Docker, рекомендуется)

```bash
docker compose up
# открыть http://localhost:8000
```

### Вручную

```bash
python -m venv .venv
source .venv/bin/activate            # Windows: .venv\Scripts\activate
pip install -e ".[dev]"

# собрать веб-интерфейс
cd frontend && npm install && npm run build && cd ..

# запустить (один процесс раздаёт API и интерфейс)
uvicorn fuelcontour.api.app:app --port 8000
# открыть http://localhost:8000
```

> Если открывали интерфейс раньше и он «завис» на старой версии — сделайте
> жёсткую перезагрузку страницы: **Ctrl+Shift+R** (сброс кэша браузера).

---

## 2. Веб-интерфейс: экраны

В левом меню семь разделов. Типичный порядок работы: Данные → Решения →
Дашборд → Проверки → Сравнение → (Геополитика) → Выгрузка.

### 2.1 Данные кейса
Показывает исходные условия: спрос по годам, пять каналов снабжения, хранилище,
инвестиции, ограничения. Только для чтения (это условия задачи). У каналов —
короткие теги характера («дешёвый», «take-or-pay», «нужна инвестиция» и т.п.).

### 2.2 Импорт CSV/XLSX
Загрузка своих данных. Два режима:
- **Одна таблица** — CSV или один лист XLSX (спрос, ИЛИ каналы, ИЛИ хранилище…).
  Импортёр сам распознаёт колонки; можно поправить сопоставление вручную.
- **Все данные одним файлом** — XLSX с несколькими листами (спрос + каналы +
  хранилище + инвестиции). Меняет всё сразу. Готовый пример:
  `data/sample_import_full.xlsx`.

Структура файла нестрогая: колонки распознаются по названиям в любом порядке,
лишние игнорируются, поддержаны русские и английские заголовки, разделители
`,`/`;`/таб, единицы в скобках. Кнопка «Сбросить к исходным данным» возвращает
кейс к оригиналу.

### 2.3 Решения / план
Здесь строится план. По каждому каналу и году задаются:
- **заказ** (сколько отбираем) — верхнее поле;
- **резерв мощности** — нижнее поле.

Ниже таблицы — строки «Спрос (цель)» и «Покрытие»: покрытие пересчитывается
автоматически и подсвечивается зелёным (спрос закрыт) или красным (недобор).
Недоступные каналы (например, Lunar-ISRU без инвестиции) показаны как «—».
Отдельно — переключатели инвестиций (ворота) и ZBO-модернизации склада.

### 2.4 Дашборд
Сводка по текущему плану и сценарию: KPI (расходы, дисконтированные, CAPEX,
стоимость тонны), графики спроса/поставки/запаса и годовых расходов, таблица
баланса по годам. Всё пересчитывается автоматически при изменении плана или
сценария (переключатель сценария — в шапке).

### 2.5 Проверки
Результат контроля ограничений: список нарушений (ошибки/предупреждения) с годом,
величиной и причиной, плюс реестр рисков снабжения. Если всё в порядке —
«Нарушений не найдено».

### 2.6 Сравнение сценариев
Стандартный против стрессового на одной базе: график общего сервиса по годам с
порогом 97%, таблица с дефицитом и запасом. Показывает, где план проседает под
стрессом.

### 2.7 Геополитика (бонус)
Сценарные ценовые шоки (санкции, рост логистики, удешевление лунной доставки).
Пресеты одной кнопкой, причинная цепочка «событие → цена → расходы», сравнение
до/после. Работает на копии — контрольные данные не меняются.

### Выгрузка
Кнопки CSV/XLSX в шапке скачивают результат (по годам, каналам, экономике,
нарушениям, рискам). Числа в файле совпадают с числами на экране.

## 3. Командная строка

Полезно для воспроизводимости (жюри может проверить без интерфейса).

```bash
# показать данные кейса
python -m fuelcontour show-case

# прогнать план в сценарии
python -m fuelcontour run --scenario standard --plan results/plan_recommended.json
python -m fuelcontour run --scenario stress   --plan results/plan_recommended.json

# сравнить сценарии
python -m fuelcontour compare --plan results/plan_recommended.json

# контрольные примеры организатора V01-V10
python -m fuelcontour validate

# найти оптимальный план (MILP)
python -m fuelcontour optimize --scenario standard --save results/plan_optimized.json

# анализ чувствительности (торнадо)
python -m fuelcontour sensitivity --plan results/plan_recommended.json

# Монте-Карло оценка рисков
python -m fuelcontour montecarlo --plan results/plan_recommended.json --trials 3000 --seed 42
```

---

## 4. Инструменты анализа

- **Оптимизатор** (`optimize`) — MILP на PuLP/CBC, минимизирует дисконтированные
  расходы при всех ограничениях. Отдаёт оценку снизу и зазор до оптимума; сам
  план проверяется расчётным ядром.
- **Чувствительность** (`sensitivity`) — торнадо-анализ: какой параметр (цена
  каналов, спрос) сильнее влияет на расходы.
- **Монте-Карло** (`montecarlo`) — вероятностная оценка рисков: разыгрывает сбои
  каналов, выдаёт распределение дефицита и 95-й перцентиль (VaR). Детерминирован
  по seed.

Те же операции доступны по API: `POST /api/optimize`, `/api/sensitivity`,
`/api/montecarlo`.

---

## 5. Формат файла для импорта «всё сразу»

XLSX с листами (имена листов и колонок гибкие). Пример структуры —
`data/sample_import_full.xlsx`, сгенерирован скриптом
`tools/make_sample_import.py`.

| Лист | Что содержит | Ключевые колонки (примеры) |
|---|---|---|
| demand | спрос по годам | год, общий, критический, низкий, высокий |
| supply_sources | каналы | id, название, мощность, цена, резерв, take-or-pay, lead time, надёжность |
| storage | хранилище | id, ёмкость, потери, стоимость хранения, CAPEX |
| investments | инвестиции | id, CAPEX (или option_fee + exercise) |

Названия колонок не обязаны совпадать буквально — импортёр сопоставляет их по
смыслу.

---

## 6. Проверка результата

- Числа на всех экранах, в CLI и в выгрузке совпадают.
- Повторный запуск даёт те же числа (детерминизм; для Монте-Карло — при том же
  seed).
- Контрольные примеры кейса: `python -m fuelcontour validate` → 10/10.
- Тесты: `pytest`.
