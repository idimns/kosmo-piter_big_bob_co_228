# Топливный космоконтур 2035

Расчётный контур планирования снабжения орбитального топливного узла на
2035–2040 годы. Оператор планирует поставки и запасы, выбирает каналы,
резервирует мощности, оценивает инвестиции и контролирует стоимость и
обслуживание спроса. Поддержаны стандартный и стрессовый сценарии, сравнение и
выгрузка результатов.

## Что это

- **Расчётное ядро** (`src/fuelcontour/engine`) — чистый Python, конвейер из
  стадий: доступность → материальный баланс → сервис → экономика → проверка
  ограничений → риски → сценарии. Единый результат для CLI, API и выгрузки.
- **CLI** — запуск и воспроизводимость без интерфейса.
- **API + веб-интерфейс** — рабочее место оператора (добавляется поверх ядра).

## Требования

- Python 3.11+
- Зависимости из `pyproject.toml` (pydantic, pyyaml, pandas, openpyxl,
  fastapi, uvicorn).

## Установка и запуск

```bash
python -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -e ".[dev]"
```

Проверка данных кейса:

```bash
python -m fuelcontour show-case
```

Прогон стандартного сценария с примером плана:

```bash
python -m fuelcontour run --scenario standard --plan results/plan_standard.json
```

Сравнение стандартного и стрессового сценариев:

```bash
python -m fuelcontour compare --plan results/plan_standard.json
```

## Порядок проверки (для жюри)

1. Установка и запуск (см. выше).
2. Стандартный сценарий: `run --scenario standard --plan results/plan_standard.json`.
3. Обязательный стресс-тест: `run --scenario stress --plan results/plan_standard.json`.
4. Сравнение: `compare --plan results/plan_standard.json`.
5. Тесты (контрольные и граничные примеры): `pytest`.

## Структура репозитория

```
src/fuelcontour/
  model/       pydantic-сущности (данные кейса, сценарии, решения)
  engine/      расчётное ядро (7 стадий + единый Result)
  io/          загрузка YAML/JSON, сохранение планов
  cli.py       командная строка
data/          исходные условия кейса (case.yaml)
configs/       сценарии: standard.yaml, stress.yaml
tests/         контрольные, граничные и golden-примеры
results/       сохранённые планы и выгрузки
docs/          управленческая записка, источники, презентация
```

## Модель: ключевые принципы

- Материальный баланс: `запас_конец = запас_начало + поступление − потери − выдача`.
  Потери учитываются один раз (коэффициент оборота хранилища).
- Переменный платёж: `цена × max(отбор, take_or_pay × резерв)` — обязательство
  take-or-pay не удваивается.
- Надёжность каналов не умножает объёмы автоматически; она учитывается в
  отдельном блоке рисков.
- Резерв мощности и физический запас — разные сущности, не суммируются.
- Все суммы в постоянных ценах 2035; ставка дисконтирования раскрыта в
  `configs/*.yaml`.

Научное обоснование методов и допущений — в `docs/sources.md`.

## Единицы и обозначения

- Объёмы: т/год. Деньги: млн условных денежных единиц (постоянные цены 2035).
- Горизонт: 2035–2040. Временной шаг физики — год (внутригодовые проверки
  запаса и ёмкости в разработке).
